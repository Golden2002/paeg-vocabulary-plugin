> 基线位置：14.3_paeg-vocabulary-plugin @ 32539f9（v0.1.0 完整快照）

## 三项诚实标注（必须知悉，禁止臆造）

1. **Word（.docx）导出不存在**：全仓库无任何 docx 生成代码，仅 **HTML / PDF / Markdown** 三种导出。
2. **图像 OCR 不存在**：仓库的 "OCR" 是扫描 PDF 文本层的"OCR 断裂修复"（连字符断词/拼接词/编码修复）与噪声剔除，无 tesseract/pytesseract/paddleocr 等图像识别代码。
3. **数据文件未完全接线**：`data/` 下 `ecdict.csv`(65MB)、`cefrj.csv`、`octanove.csv`、`lemma.en.txt` 已由下载脚本下载且入库，但运行时代码未引用；代码实际消费的是 `cmudict.dict`、`cefr_words.csv`、`oxford3000.tsv`、`kaikki_topic_*.jsonl`、`headwords*1000.txt`、`level_matrix.json`。

## 四、诚实性备注（禁止臆造原则——与文档声称不符或需澄清的点）

1. **Word 导出不存在**：任务点名的"PDF/Word/Markdown 导出"中，**Word(.docx) 导出在基线中无任何实现**（grep 全仓库无 docx 相关代码）；实际导出为 **HTML / PDF / Markdown** 三种。
2. **图像 OCR 不存在**：基线无 tesseract/pytesseract/paddleocr；"OCR"仅指对已有文本层（扫描书提取出的文本）做断裂修复与噪声剔除。真正的扫描件图像识别不在本基线能力内。
3. **部分已下载数据未被代码消费**：`ecdict.csv`(66MB)、`cefrj.csv`、`octanove.csv`、`lemma.en.txt` 已入库但运行时代码未引用（仅下载脚本与 README 提及）；代码实际消费 `cmudict.dict`、`cefr_words.csv`、`oxford3000.tsv`、`kaikki_topic_*.jsonl`、`headwords*1000.txt`、`level_matrix.json`。这属于"数据已备、接线未完成"状态。
4. **docs/ 目录为空**；pyproject 声明 `prompts/*.py` package-data 但 `prompts/` 目录不存在（打包配置与源码不一致）。
5. **audio 字段（发音 URL）**在 VocabularyEntry 模型中存在，但全流程无填充逻辑（模型级占位，非能力）。
6. **README 测试数（60/60）已过时**，实测为 148+6=154 全绿；CHANGELOG 中 148 与实际一致。
7. **web_api.py 无 `__main__`/`app.run`**，需 `flask --app web_api run` 或宿主项目加载（README 未说明启动方式）。
8. **spaCy 未安装时自动降级**：词元化退化为小写、POS 默认 NOUN（本会话实测环境即此状态，148 测试仍全绿，说明降级路径稳定）。
